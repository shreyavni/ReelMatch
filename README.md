# Reel Match — AI Movie Recommendation Web App

A full-stack content-based movie recommendation system. Enter a movie you like,
and the app returns 10 similar titles — each with **poster, rating, genres,
and description** — pulled straight from the trained dataset (no external API
calls needed at request time, so it stays fast and doesn't depend on any
third-party rate limits).

---

## 1. How it works

- **Dataset:** `TMDB + IMDB Movies Dataset.csv` (~268 MB, 441k rows).
- **Filtering:** cleaned to Released, non-adult titles with a poster and a
  real overview, `vote_count >= 30`, then ranked by a blend of popularity and
  vote count and cut down to the **top 12,000 movies**. This keeps the
  deployed model small and fast while covering all the well-known titles a
  user is likely to search for.
- **Model:** a **TF-IDF vectorizer** over each movie's overview, tagline,
  genres, keywords, director, and top-5 cast members, combined with a
  **Nearest Neighbors (cosine similarity)** index. This is a classic,
  lightweight content-based recommender — no heavy deep-learning model, no
  GPU needed, loads in under a second.
- **Artifacts:** the trained model is saved once as gzip-compressed pickle
  files (~14 MB total) in `backend/model_artifacts/`. The Flask server loads
  these **once at startup**, not on every request.
- **Posters / ratings / descriptions:** already present in the source
  dataset (`poster_path`, `vote_average`, `overview`). Posters are served via
  TMDB's public image CDN (`https://image.tmdb.org/t/p/w500/<path>`), so no
  API key or extra network calls are required.

## 3. Running locally

```bash
cd backend
pip install -r requirements.txt
python app.py
```

Open `http://127.0.0.1:5000` in your browser. The frontend and API are
served from the same Flask app, so there's nothing else to configure.

## 4. Retraining the model (optional)

The model artifacts are already included in `backend/model_artifacts/`, so
you don't need to retrain to deploy. If you want to regenerate them (e.g.
with a different dataset revision):

```bash
cd train
python prepare_and_train.py
```

This reads the raw CSV, filters/ranks it down to the top movies, fits the
TF-IDF + Nearest Neighbors model, and overwrites the files in
`backend/model_artifacts/`. **The raw 268 MB CSV is not committed to GitHub**
or deployed — only the ~14 MB trained artifacts are.

## 5. API Reference

| Endpoint | Method | Purpose |
|---|---|---|
| `/health` | GET | Returns server + model status. |
| `/movies?q=<text>` | GET | Lightweight title search for autocomplete. |
| `/recommend` | POST | Body `{"movie": "<title>"}` → returns 10 similar movies as JSON. |

Example:

```bash
curl -X POST http://127.0.0.1:5000/recommend \
  -H "Content-Type: application/json" \
  -d '{"movie": "Inception"}'
```

All errors (missing field, bad JSON, movie not found, wrong HTTP method,
unknown route) return a clean JSON error object with an appropriate status
code — the server never crashes or shows a raw 500 page. See
`docs/API_TESTING.md` for the full Postman test log.

## 6. Deployment

### Render

1. Push this project to a GitHub repository (make sure `dataset_extract/`
   and the raw `.csv` are **not** included — see `.gitignore`).
2. On [render.com](https://render.com), create a **New Web Service** and
   connect your repo.
3. Set:
   - **Root directory:** `backend`
   - **Build command:** `pip install -r requirements.txt`
   - **Start command:** `gunicorn app:app --bind 0.0.0.0:$PORT`
4. Deploy. Render provides the `PORT` environment variable automatically —
   `app.py` already reads it via `os.environ.get("PORT", 5000)`.
5. **Cold start note:** Render's free tier spins down after inactivity. The
   first request after idling can take **30–60 seconds** while the instance
   wakes up; subsequent requests respond in well under a second (tested
   locally at ~50 ms for `/recommend`).

## 7. Performance notes

- `/recommend` responds in **~50 ms** once the server is warm (well inside
  the 3–5 second target).
- Total model footprint is **~14 MB**, comfortably inside free-tier memory
  limits (typically 512 MB).
- The model loads once at process startup, not per request.
